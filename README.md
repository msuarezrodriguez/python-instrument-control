# Automated Transport Measurements – Python Control Framework

This repository contains a modular Python framework to run automated electrical transport measurements (I–V and temperature sweeps) using GPIB-controlled laboratory equipment. 

It is designed to replace or complement existing LabVIEW-based measurement routines with a more flexible, scriptable, and version-controlled Python workflow.

Currently, the framework supports:

- **Keithley 2634B** source-measure unit (SMU)
- **LakeShore 336** temperature controller

with built-in measurement modes for:

- Voltage-source I–V curves  
- Current-source I–V curves  
- Voltage vs temperature at fixed current  
- Current vs temperature at fixed voltage  

The code is structured to be easily extendable to additional instruments and measurement protocols.

For illustration, a small demonstration using a Pt sample is included in the repository. 
It shows how measurement files are generated by the framework and how they can be analyzed in a very simple Jupyter notebook.

In the next development steps, this framework will be extended to control and coordinate further equipment, including:

- **Keithley 6221** current source  
- **Keithley 2182A** nanovoltmeter  
- **NF LI5660** lock-in amplifier  
- **Quantum Design PPMS** cryostate with temperature and magnetic field control

---

## Features

- **Scriptable measurement configuration** via a `MEASUREMENTS` list of dictionaries in `main.py`
- **Multiple measurement modes**:
  - `voltage`: voltage-source I–V (measure I(V))
  - `current`: current-source I–V (measure V(I))
  - `v_vs_t_current`: V(T) at fixed current during a temperature ramp
  - `i_vs_t_voltage`: I(T) at fixed voltage during a temperature ramp
- **Optional temperature stabilization** before I–V sweeps using a LakeShore 336
- **Continuous temperature ramps** for V(T) and I(T) measurements, without per-point stabilization
- **Automatic data directory creation** based on user and device identifiers
- **Convenient data saving utilities** for I–V and temperature-sweep measurements

The design emphasizes:

- Clear separation between **instrument drivers**, **measurement logic**, and **I/O utilities**
- A measurement configuration that is **easy to read, edit, and extend**
- Safe shutdown of instruments even in case of interruption (e.g., `Ctrl+C`)

├── config/
│   └── paths.py            # Data directory handling (e.g. make_data_dir)
├── instruments/
│   ├── keithley_2634b.py   # Keithley 2634B SMU driver
│   └── lakeshore_336.py    # LakeShore 336 temperature controller driver

    ├── IV.py               # I–V measurement routines
    ├── temp_sweep.py       # V(T) and I(T) sweep routines
